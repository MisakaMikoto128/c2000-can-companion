# docs/架构.md（Companion 仓库）

## 分层

| 层 | 文件 | 职责 |
|---|---|---|
| 界面 | `static_host/index.html + app.js + watch.js` | 页面渲染、用户交互；状态由后端推送（onPush），1 s 轮询兜底 |
| 桥 | `host_app.py` | pywebview js_api：界面调用的全部入口；内部字段 `_` 前缀避免被 pywebview 递归遍历 |
| 设备抽象 | `watch.py` | WATCH 引擎：DWARF/COFF 符号解析、轮询状态机（地址合并、总线预算、原子快照）、读写会话 |
| 升级 | `upgrade/bl_client.py` 等 | Bootloader 客户端：编码协商、块传输与重发、增量规划（`selective.py`） |
| 通道 | `upgrade/can_channel.py` | 订阅分发：帧只投递不取走，每个消费者一个私有信箱，先订阅后发送不丢应答 |
| 总线 | `canbus.py` | ZLG USBCAN2 驱动；收发同线程（厂商 Receive 非阻塞实证），发送走队列保持同步外观 |
| 协议 | `protocol.py` + `upgrade/bl_protocol.py` | dev 0x0C 段帧 ID 构造/解析与载荷编解码；与固件 `can_dev.h` 单一来源对齐 |

## 线程模型

- 一个 I/O 线程独占 CAN DLL：接收分发 + 发送队列排空都在它上面。
- 一个后台任务队列（单工人）跑所有 CAN 往返命令，js_api 只投递，UI 线程不阻塞。
- 一个推送线程 50 ms 一拍：状态版本号变化才把快照推给前端。
- 升级/观察各自的工作线程通过信箱（订阅谓词）取应答，互不抢帧。

## 启动链

`start_gui.bat` → `python -m monitor_tui.host_app` → 命名互斥量单实例 → 读 `index.html` 盖 `?v=` 时间戳生成 `_index_live.html`（绕过 WebView2 持久缓存）→ `webview.create_window(private_mode=False)`（localStorage 落盘）→ 自动连接 CAN → 广播探测。
